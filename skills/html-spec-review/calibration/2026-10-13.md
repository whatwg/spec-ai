# Calibration run — 2026-10-13

Method and results of running `html-spec-review` against 10 randomly chosen recent `whatwg/html` PRs, used to prune and tighten `html-style-guide.md`.

Per foolip's suggestion on [whatwg/spec-ai#2](https://github.com/whatwg/spec-ai/pull/2#pullrequestreview-5503532419): run the skill on randomly chosen recent PRs, including merged ones, to reveal common false positives and rules that editors do not enforce in practice. Sample: `random.seed(2026)` over PRs #12800–#13060 → 6 merged, 4 open. One subagent per PR applied the style guide and `SKILL.md` to the added/changed lines only, then compared against the actual human review comments.

## 2. Rules removed or consolidated after calibration and review

| Former rule(s) | Why it was noisy, unclear, or redundant | Action |
|---|---|---|
| `VAL-NULL` | Originally banned `"is non-null"`, which is used ~110 times in `source` (and in `SKILL.md` itself); boolean flags and optional args are already covered by `DFN-NO-FLAGS` and `ALG-PREAMBLE`. | **Removed** (and restored `"is non-null"` in `SKILL.md`). |
| `PRS-MECHANICS` | Demanded `&mdash;` over UTF-8 `—`, flagged contractions in re-wrapped text (#12972), and bundled unrelated prose advice. | **Removed** (pluralizing outside `<code>` kept in `XREF-CODE`). |
| `ALG-PARAM-TYPES`, `ALG-OPTIONAL-ARGS`, `ALG-RETURN-SENTENCE`, `ALG-HOOKS` | Split [Infra § Algorithm declaration](https://infra.spec.whatwg.org/#algorithm-declaration) and [§ Algorithm parameters](https://infra.spec.whatwg.org/#algorithm-params) into 5 rules and over-fired on hook preambles (`"…, run these steps:"`) and obvious return/parameter types. | **Consolidated into `ALG-PREAMBLE`**, deferring to Infra and stating only HTML's `<div algorithm>` wrapper, `TYPE-or-null` spelling, and hook preambles. |
| `ALG-NON-NORMATIVE-NOTES`, `BLK-NOTE-STALE` | Over-fired on parenthetical glosses; stale notes are already covered in `SKILL.md` §10.3/§17. | **Removed** (note placement kept in `BLK-NOTE`). |

## 3. Scope and rule refinements retained

- **Scope:** Style rules apply only to *new or rewritten normative text* — not to notes, examples, `dl.domintro`, re-wrapped lines, revert-restored text, or a single step added inside an algorithm written in a Legacy style.
- **Infra vs. HTML:** Rules that build on the Infra Standard carry an **Infra:** link so reviewers cite Infra for cross-spec conventions and treat HTML-only rules separately.
- **Resulting size:** Pruned from 83 rules (909 lines) to **50 rules** (480 lines) across 10 sections.
